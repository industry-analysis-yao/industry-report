# Industry Report

大王製紙向けの家庭紙・衛生用品・関連設備の情報ダッシュボード。

## 収集・選定（2026-09-13 更新）

- メーカー17社の公式一覧/APIを直接収集：ユニ・チャーム、日本製紙（クレシア含む）、花王、大王製紙、王子ホールディングス、瑞光、フジキカイ、安川電機、大森機械工業、川島製作所、Universal Robots、Valmet、ANDRITZ、Orbbec、エー・アンド・デイ、パナソニックコネクト、コニカミノルタ。
- Google News は日本語・英語・中国語それぞれの地域設定で110組の検索を実行。`scripts/source_catalog.py` にメーカー・用途別の検索を集約し、包装機・ロボットに「おむつ」の同時出現を要求しない。包装検査・計量・印字設備も対象。Automation News の公開API、PR TIMES・ロボスタ・IoTNEWSのRSSも直接確認する。
- Google News RSS は補助的な発見経路。RSS 日時だけでは日報に採用しない。
- 公式一覧では、同じ行／JSON レコードのタイトル・リンクに結びついた公開日だけを採用する。日本製紙は `pub_on`、花王はニュース索引の `time`、HTML は各発表行の表示日付。`mod_on`、サイト構築日時、PDF 更新日時は使わない。
- 本文の明示的な初回公開日が一覧より古い場合は古い日付を優先。本文取得不能・原文日付未確認は日報対象外。PDF は最初の4ページまでを抽出し、日付は公式索引の公開日を保持。
- 30日間の過去日報との URL・指紋・類似タイトル／記事内容による照合を通過した候補から、目標20件を選ぶ。同日再実行はその日の既刊分を重複扱いしない。
- 日本時間の直近3暦日を優先し、不足時は4〜5日目の未掲載分を検討する。5暦日を超える候補は、高得点・初発見・設備記事でも日報に入れない（9月10日の対象は9月6〜10日）。30日は重複照合期間であり、掲載可能な古さではない。候補庫の60日保持とも区別する。
- 明示的な出典リンクのある Automation News 記事はメーカーの元発表を1段追跡。元発表が古い場合は古い日付を採用し、媒体の再報道日は別途証拠として保存する。全サイトの転載・翻訳を完全に認識できるわけではない。
- 特許は別枠。製品ニュース内の「特許技術」という表現だけでは特許公開として扱わない。
- 化粧品・ペットフード・スポーツ等は公式サイトの掲載であっても対象外。メーカーの事業・工場・原材料・関連技術は対象。

## 要約・スコア

`OPENROUTER_API_KEY` が設定されている場合はAI要約・審査を行う。利用不能／予算上限の場合も、検証済みの原文を捨てず、**原文抜粋・ルール評価**と明示する。AI分析を捏造しない。

日付・本文・関連性・30日既刊照合を先に実施し、AIは新規掲載可能候補だけを最大80件、分野別に巡回して審査する。短いRSS要約ではなく保存した原文を入力する。否決理由と原文指紋・規則バージョンを候補に保持し、翌日の同一候補の再審査を抑制する。既刊の同日再実行では有効な発表をAIで再判定しない。本文や規則が変われば否決キャッシュは失効する。

ルール評価は関連性（最大35）・影響度（最大28）・出典信頼性（最大20）・鮮度（最大15）の合計。各内訳は `score_components` に保存する。AI評価と異なる方式であり、絶対的な精密評価ではない。

## 実行・検証

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/fetch_news.py --dry-run --json-output work/fetch-preview.json
python scripts/fetch_news.py
python scripts/generate_dashboard.py
python scripts/validate_digest.py
```

`--query-limit 0` は公式メーカーと特許だけの試験、`--no-enrich` は本文取得を省く調査用。定常運転で本文取得を省略しない。

GitHub Actions は毎日07:05 JSTに収集する（遅延はあり得る）。**土日は収集のみ、月〜金に日報を作成**し、土日の候補を既刊履歴に消費しない。実行時のJST曜日で判定する。ホーム画面は週末に直近の平日版を実際の発行日で表示し、過去の週末版は履歴から参照可能。検索は最大60件/組、本文確認は最大240件。4並列・タイムアウト付き検索を使い、本文確認は用途別に順番を回す。確認済みの既知リンクは再確認枠を消費しない（抽出ロジックのバージョン変更時は再検証）。

`Verify Real AI Pipeline (no publication)` はコード変更時に本番と同じAIキーで収集・要約・検証を実行する。データは一時ディレクトリにコピーし、本番日報や履歴は変更しない。週末試験には独立した `--data-dir` と `--allow-weekend-preview` が必要。結果と候補別判定は実行アーティファクトで確認する。合成データでの5日×20件テストは選定ロジックの検証であり、実際の供給量を証明しない。

## 数量不足の診断

- `data/collection_health.json`：取得日時、公式17社の解析件数・直近5日件数、検索別の総取得数・日付候補数・除外理由、本文の日付確認済み件数。正常に取得できたが最近の発表がない状態と、取得エラーを区別する。
- `data/selection_audit.json`：直近平日の日報作成時の全候補のURL・真の公開日・段階別除外理由・AI否決理由。`date`で対象回を確認する（週末は上書きしない）。
- `data/YYYY-MM-DD.json` の `selection_health`：採用数／目標、確認済み候補、30日履歴との重複、AI対象外判定、排他的な分野別件数。
- 20件未達は Actions 警告と実行サマリーに表示する。候補不足の理由を隠さない。

20件は収集・選定目標であり、毎日20件の新発表があることは保証できない。不足時に既刊の再掲や旧記事の日付改変はしない。設備の欄を埋めるために無関係な家電、原子炉、金属材料などを採用しない。低頻度メーカーの過去の技術情報は日報とは別に扱う。公式サイトの構造変更・取得失敗は診断ファイルから検出し、ソースを修正・拡充する。
